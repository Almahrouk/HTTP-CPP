Webserv
Custom HTTP Server in C++

A fully functional HTTP server built from scratch in C++98. It handles real HTTP requests from browsers and clients, operates entirely non-blocking using a single poll() call for all I/O operations, serves static files, executes CGI scripts, and processes file uploads.

Key Features

Every feature carefully implemented to comply with the HTTP/1.1 specification while maintaining a clean, efficient architecture.

⚡
Non-Blocking I/O
Single poll() loop multiplexing all client connections. No threading, no forking — pure event-driven architecture.
📨
HTTP Request Parsing
Full parsing of GET, POST, and DELETE methods with header extraction, chunked transfer decoding, and body handling.
📁
Static File Serving
Efficient file serving with correct MIME types, content-length headers, and proper HTTP status codes.
📤
File Uploads
Multipart form-data parsing for file uploads with configurable maximum body size limits.
⚙️
CGI Execution
Execute Python and PHP scripts via CGI protocol. Proper environment variable setup, stdin/stdout piping, and timeout handling.
🚫
Custom Error Pages
Configurable error pages for each status code (404, 405, 413, 500, etc.) served with correct HTTP semantics.
📂
Autoindex
Automatic directory listing when no index file is present. Toggleable per-route in the configuration file.
🔧
Configuration System
NGINX-inspired config parser supporting multiple server blocks, routes, redirections, and per-route method restrictions.
🍪
Cookies & Multi-CGI
Bonus: Cookie management via Set-Cookie/Cookie headers and support for multiple CGI interpreters.

// Event-Driven Design
A single poll() call monitors all file descriptors — listening sockets, client connections, and CGI pipes. New events are dispatched without blocking.
// Connection Lifecycle
Each client connection is tracked with its own read buffer, write buffer, and state machine. Connections are timed out after inactivity.
// Request Pipeline
Incoming bytes are accumulated, parsed into structured request objects, matched against configured routes, and dispatched to the appropriate handler.
// Modular Architecture
Clean separation between config parsing, request parsing, request handling (static/CGI/upload), and response building. Each module is independently testable.
