Phase 0 Theory & setup Days 1–3 ▶

Every requirement — config file format, methods, CGI, errors, edge cases

RFC 7230–7235, request/response cycle, headers, status codes

Nginx as reference

Git repo & Makefile

Set up repo with -Wall -Wextra -Werror -std=c++98 flags from day one

💡 Study nginx config format closely — your config parser must mimic it. Nginx is your spec.
Phase 1 Config file parser Days 4–7 ▶
Tokenizer

Parse server blocks, location blocks, and individual directives

Core directives

listen, server_name, root, index, error_page, client_max_body_size

Location block

Allowed methods, autoindex on/off, return (redirect), cgi_pass

Validation & errors

Invalid config must print a clear error and exit — never silently continue

💡 A well-structured config struct makes every other module cleaner. Invest time here.
Phase 2 Socket & I/O loop Days 8–12 ▶
TCP socket setup

socket(), bind(), listen(), accept() — all set to non-blocking with fcntl()

poll() event loop

Single poll() call monitors all file descriptors — server fds + client fds

Multiple ports

Support several server blocks listening on different ports simultaneously

Client lifecycle

Accept → read → parse → respond → close/keep-alive, all non-blocking

⚠ poll() must be the only wait point. Never call recv, send, or accept outside the I/O loop — this is the most common eval failure.
Phase 3 HTTP engine Days 13–20 ▶
Request parser

Method, URI, HTTP version, headers, body — chunked transfer + Content-Length

GET

Serve static files, index fallback, autoindex directory listing in HTML

POST

Read request body, save uploaded file, enforce max body size with 413

DELETE

Remove target file, return 204 on success, 404 if not found

Status codes

200 201 204 301 302 400 403 404 405 413 500 502 — all must be correct

Custom error pages

Serve user-defined HTML pages for configured error codes from config

💡 Use curl -v religiously — it shows you exactly what bytes go over the wire.
Phase 4 CGI Days 21–26 ▶
fork() + execve()

Launch CGI binary (.py, .php) per request in a child process

Environment variables

REQUEST_METHOD, QUERY_STRING, CONTENT_TYPE, CONTENT_LENGTH, PATH_INFO…

Stdin/stdout pipes

POST body → CGI stdin. CGI stdout → HTTP response body

Timeout & cleanup

Kill hanging CGI with SIGKILL + waitpid(). No zombie processes.

⚠ CGI timeout handling is mandatory — a hanging script must not block your server. Use waitpid() with WNOHANG in your poll loop.
Phase 5 Testing & polish Days 27–35 ▶
curl tests

All methods, edge cases, large bodies, bad requests, missing headers

Browser test

Chrome/Firefox — full page load, forms, file uploads, redirects

Stress test

siege or ab — no crash, no hang, no zombie CGI processes under load

Valgrind

Zero memory leaks before eval day — especially after CGI and long runs

Error resilience

Bad config, missing files, broken pipes, signal handling — all graceful

Makefile rules

all, clean, fclean, re — no unexpected relink, no missing deps

03

Eval checklist

  • Non-blocking I/O only poll/select is the only wait. Never recv/send/accept outside the loop.
  • Accurate HTTP parsing Malformed requests return 400, not a crash or silent hang.
  • Multiple server blocks Different ports, multiple server_names on same port — all handled.
  • Static file serving index.html fallback, custom error pages, autoindex directory listing.
  • POST file upload File saved to correct path, max body size enforced with 413.
  • DELETE method Returns 204 on success, 404 if file not found, 403 if no permission.
  • CGI works correctly .py and .php scripts return correct output via fork + execve + pipes.
  • Redirects work 301/302 via return directive in config sends Location header.
  • Browser compatible Full page load in Chrome/Firefox without hanging or partial content.
  • Stress test passes No crash, no hang, no zombie processes under siege / ab load.
  • Zero memory leaks Valgrind clean — especially in CGI fork paths and long-running server.
  • Makefile rules all clean fclean re — no unexpected relink, no missing dependencies.
